# Fuel Procurement Decision

Dashboard ช่วยตัดสินใจซื้อน้ำมัน (ดีเซล / แก๊สโซฮอล์ 95) — สร้างหน้าเว็บทุกรอบด้วย GitHub Actions (`.github/workflows/update_dashboard.yml`)

## หลักการตัดสินใจ

คำแนะนำมาจาก **ความน่าจะเป็นที่ราคาต่ำสุดของตลาดจะขึ้น/ลงข้ามคืน** (เทียบ 15:30 วันนี้ กับ 15:30 พรุ่งนี้ เพราะราคาเป็นฟันเลื่อย:
ขึ้นก้อนใหญ่ข้ามคืนแล้วค่อย ๆ ลดทั้งวัน) ไม่ใช่ rule if/else ตามสถานะ MOPS/กองทุน เหมือนเดิม

| ไฟล์ | หน้าที่ |
|---|---|
| `signals.py` | ฟีเจอร์ที่ "รู้แล้ว ณ เวลาตัดสินใจ" (Trend Mops ระหว่างวัน, ประกาศ "มีปรับขึ้น/ลง", MOPS ปิด, ประกาศกองทุน) + `PriceBook` (ราคาต่ำสุดตลาด) |
| `model.py` | โลจิสติกส์เล็ก ๆ (numpy) + เกณฑ์แปลงเป็น เร่งซื้อ / ทยอยซื้อ / ซื้อปกติ / ชะลอ |
| `engine.py` | ตรวจความสดของฟีด → เลือกโมเดลตามช่วง (PM ก่อน ~19:00 / EVE หลังรู้ MOPS ปิดและกองทุน) → เหตุผล + หลักฐานย้อนหลัง; ฟีดหาย/เก่า = "ข้อมูลไม่พอ" ไม่ใช้ค่าค้าง |
| `fit_model.py` | ฝึกและวัด walk-forward → `model_params.json`, `backtest_summary.json` |
| `ingest.py` | คัดลอกฟีดจากชีท OIL BOT (`Entry_Intraday`, `Entry_HeadsUp`, `Entry_FundNotice`, `Entry_MopsClose`, `Entry_Prices`) + EPPO/MOPS/กองทุนเดิม (EPPO มีคอลัมน์ `Source` = FRESH/CARRIED) |
| `log_decisions.py` | บันทึกคำแนะนำจริงลงแท็บ `DecisionLog` แล้วเติมผลลัพธ์เมื่อรู้ราคาวันถัดไป |
| `check_models.py` | ตรวจรายสัปดาห์ (workflow `check_deepseek_models.yml`) ว่าโมเดล DeepSeek ที่ worker/news.py ใช้ยังอยู่ในรายชื่อและเรียกได้จริง (ข้อความ + รูป) ล้มให้เห็นชัดเมื่อโมเดลหาย |
| `main.py` | สร้าง `index.html` (+ `decision_snapshot.json`) ; ตรวจความสดของข้อมูลแล้วแสดงคำเตือน |

## แผนส่งรถ (สรุปสำหรับทีมจัดซื้อ)

ระยะเดินทางสาขา → คลัง 8–12 ชม. ราคาที่ซื้อได้จริงคือราคา ณ เวลารถถึงคลัง (เวลาออก + ระยะเดินทาง) หน้าเว็บจึงมีส่วน "ส่งรถตอนนี้ดีไหม?" ต่อชนิดน้ำมัน:

- โมเดล `{ชนิด}_{ช่วง}_L{ชม.}` ช่วงตัดสินใจ D06/D12/D15/D20 (06:00/12:00/15:30/20:30) x ระยะเดินทาง 8/10/12 ; เป้าหมาย = ราคาตลาดต่ำสุด ณ เวลาถึง A+24 ชม. ลบ ณ เวลาถึง A (บวก = รอแล้วแพงขึ้น)
- ฝึกด้วย `python3 fit_model.py <data_dir> --dispatch-only` (รวมเข้า `model_params.json`/`backtest_summary.json` เดิม ไม่แตะโมเดลเดิม)
- เกรดความเชื่อมั่นต่อช่วง (ดี/พอใช้/อ่อน) จาก AUC + ผลช่วงที่ไม่เคยใช้จูน ; เกรด "อ่อน" บังคับเป็น "ส่งตามแผนปกติ" ไม่แนะนำเร่ง/ชะลอ
- ก่อน 06:00 ไม่ประเมิน
- ทดสอบเดินหน้า (forward test): `log_dispatch.py` บันทึกคำแนะนำทุกรอบลงแท็บ `DispatchLog` (append อย่างเดียว ไม่แก้ย้อนหลัง) แล้วเติม `outcome_delta` = ราคาตลาด ณ เวลาถึง+24 ชม. − ณ เวลาถึง เมื่อเลยเวลานั้น ; หน้าเว็บสรุปผลต่อชนิดเมื่อมีผลครบ 20 วัน (นับ 1 รอบแรกต่อ วัน/ช่วง) ก่อนหน้านั้นแสดงว่ากำลังสะสม

เมื่อ `DecisionLog` สะสมผลลัพธ์พอ (>= 20 วันต่อชนิด/ช่วง/คำแนะนำ) หน้าเว็บจะแสดงสถิติใช้งานจริงแทน backtest

## แนวโน้มราคา 24/48 ชม. (ข้อความกลาง)

การ์ดบนหน้าแรกบอก "ขึ้นแรง / ขึ้น / ยังไม่ชัดเจน / ลง / ลงแรง" ของราคาต่ำสุดของตลาดข้างหน้า 24 และ 48 ชม. จากข้อมูล 20:30 น. (หลังประกาศกองทุน + MOPS ปิด)
ไม่ระบุเวลาออกรถ ให้แต่ละสาขาจัดสรรเอง พร้อมความเชื่อมั่น สูง/กลาง/ต่ำ ที่คำนวณจาก walk-forward (ถูกทิศ/ผิดทิศ ความนิ่งครึ่งแรก-ครึ่งหลัง จำนวนครั้ง)
- เกณฑ์: ขยับ ≥10 สต./ลิตร = ขึ้น/ลง ; ≥40 สต. = แรง ; โอกาส <50% = ยังไม่ชัดเจน (ไม่ทาย "ทรงตัว" เพราะย้อนหลังไม่แม่น)
- ฝึก: `python fit_model.py <data_dir> --outlook-only` (ไม่แตะโมเดลอื่น) ; การฝึกซ้ำรายสัปดาห์ยังไม่ปรับโมเดลส่วนนี้ (คงของเดิม)
- ทดสอบเดินหน้า: `log_outlook.py` บันทึกลงแท็บ OutlookLog (รอบแรกของ 20:30 แต่ละวัน) แล้วเติมผลจริงหลังครบ 24/48 ชม.
- `outlook.json` (ข้อความ + ระดับ) ถูกเผยแพร่คู่กับ index.html ให้ oil-bot ดึงไปส่งเข้าไลน์ตามคำขอ
